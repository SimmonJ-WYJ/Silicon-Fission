# 渠道编辑与删除设计

## 目标

让管理员在 Silicon Fission `/admin` 简化后台安全地编辑和删除已保存渠道，不再需要进入 new-api 完整后台。普通用户不可访问这些操作。

## 管理界面

每个渠道行新增两个操作：

- **编辑**：打开模态窗口，可修改渠道名称、上游 Base URL、开放模型、启用状态和可选的新上游 API Key。
- **删除**：打开危险操作确认窗口，管理员必须输入完整渠道名称后才能提交删除。

编辑窗口永不回显旧 Key。新 Key 输入框留空表示保留现有 Key，填写非空值才替换。保存成功后关闭窗口并刷新渠道列表；失败时保留输入内容并显示后端错误。

## API 设计

新增 `/api/admin/channels/[id]`：

- `PUT`：更新渠道参数。
- `DELETE`：删除渠道。

两种方法都验证管理员会话和十进制渠道 ID。

### 更新流程

请求字段为：`name`、`baseUrl`、`models`、`enabled` 和可选 `key`。

1. 验证名称和模型非空，状态为布尔值。
2. 从 new-api `GET /api/channel/:id` 获取不含明文 Key 的现有渠道对象。
3. 合并允许编辑的字段，保留渠道类型、分组、优先级和其他底层配置。
4. `key` 为空时不向 new-api 提交 Key；非空时提交新 Key 完成轮换。
5. 通过 `PUT /api/channel/` 更新普通字段。
6. 若启用状态发生变化，通过 `POST /api/channel/:id/status` 更新状态。

new-api 官方更新实现对空 Key 使用零值更新语义，因此不会清空已有 Key；本应用仍主动省略空 Key，进一步避免误覆盖。

### 删除流程

请求体包含 `confirmName`。服务端先读取渠道详情，并使用精确字符串比较确认名称；不匹配时返回 HTTP 400。匹配后调用 new-api `DELETE /api/channel/:id`。这使确认不只依赖浏览器界面，直接调用 API 也不能绕过名称确认。

## Demo 模式

Demo 模式在渠道 Cookie 中执行相同的编辑和删除行为：

- 编辑保留未修改字段并更新允许字段。
- 删除同样要求名称精确匹配。
- Demo 不保存或展示真实上游 Key。

## 错误和一致性

- 非法 ID、缺少必填字段、错误状态类型、确认名称不匹配：HTTP 400。
- 未登录：HTTP 401。
- 渠道不存在：HTTP 404（若 new-api 未区分，则透传明确错误信息）。
- new-api 拒绝操作：向前端返回其错误信息。
- 普通字段更新成功但状态更新失败时，返回明确的“参数已更新但状态更新失败”错误，提醒管理员刷新后重试状态。
- 删除成功后立即刷新列表和模型列表来源；正在进行中的请求不保证被中断，后续请求不再路由到该渠道。

## 安全约束

- API Key 永不通过列表、详情或编辑接口返回。
- API Key 不写入日志、错误信息或确认弹窗。
- 删除按钮使用危险色，确认按钮在名称完全匹配前保持禁用。
- 删除不可撤销；界面明确提示关联模型可能立即不可用。

## 测试与验收

- 单元测试覆盖渠道 ID、更新字段、空 Key 省略、新 Key 替换和删除名称确认。
- API 测试或可测试纯函数验证合并结果不会改变渠道类型和底层配置。
- Demo 编辑与删除行为可重复验证。
- TypeScript 检查、自动化测试和生产构建通过。
- 线上管理员可以编辑 `BananaRouter-*` 渠道并重新测试连通。
- 删除测试渠道后列表立即消失；其他渠道不受影响。
