# Siliconfission 独立公开落地页设计

日期：2026-08-03

## 1. 目标

为 Siliconfission 建立一套独立公开官网，只负责品牌展示、平台能力介绍和注册转化。现有 New API 控制台、模型网关、数据库与计费系统保持不变。

成功标准：

- 公开官网与控制台不再共用同一个前端根路由。
- 刷新官网、点击官网 Logo 和从控制台返回官网时，均进入同一套公开首页。
- 首页突出“一个 API Key 接入多种大模型”的价值主张。
- 首页兼顾注册转化与技术可信度，不展示未经验证的模型数量或可用率。
- 后台顶部导航发生修改后，公开官网能自动同步。
- 中英文为两套独立内容，并支持浅色与深色主题。

## 2. 域名与服务边界

| 域名 | 职责 | 实现 |
| --- | --- | --- |
| `siliconfission.com` | 公开官网 | 独立静态前端，由 Caddy 提供 |
| `console.siliconfission.com` | 注册、登录、控制台、API Key、模型广场、排行榜及用户功能 | 反向代理到现有 `sf-new-api:3000` |
| `api.siliconfission.com` | 模型 API 调用入口 | 保持反向代理到现有 `sf-gateway:8788` |

公开官网不实现账户、密钥、模型管理、搜索或通知等业务逻辑，只提供展示与跳转。New API 和网关的数据流不做修改。

官网使用 React、Vite 和 TypeScript 构建为静态资源。交互仅用于导航配置、语言、主题、代码标签和复制按钮，不引入官网专用后端。

## 3. 顶部导航

公开官网顶部栏在视觉上与控制台保持同一套产品语言，并从 New API 的公开站点配置中读取导航项。

默认结构：

- Logo：返回 `https://siliconfission.com/`
- 首页：公开官网首页
- 控制台：进入 `https://console.siliconfission.com/`
- 模型广场：进入控制台的模型广场
- 排行榜：进入控制台的排行榜
- 搜索：进入或唤起控制台搜索功能
- 通知：进入控制台通知区域
- 语言切换：切换官网中文或英文内容
- 主题切换：切换官网浅色或深色主题
- 账户入口：显示“登录 / 注册”或中性账户图标，并进入控制台认证入口

文档入口当前关闭，不在默认导航或首屏 CTA 中出现。

后台新增、删除、排序或隐藏顶部导航项后，公开官网应在缓存过期后自动更新。导航配置缓存时间固定为 60 秒。配置请求失败时，优先使用最近一次有效缓存；没有缓存时使用内置基础菜单，不能让顶部栏消失。

后台返回的相对路径需要映射到正确域名：公开首页保留在主域名，控制台业务路径统一指向 `console.siliconfission.com`。外部完整 URL 保持原值。

## 4. 页面结构

### 4.1 首屏

采用明亮、专业的开发者基础设施风格和左右双栏布局。

中文主标题：

> 一个 API Key，连接多种大模型

中文副标题：

> 通过统一、兼容的接口接入 OpenAI 与 Claude 生态，为每个任务灵活选择合适的模型。

英文主标题：

> One API Key. Multiple AI models.

英文副标题：

> Access models across the OpenAI and Claude ecosystems through one unified, compatible interface.

主按钮为“创建 API Key / Create API Key”，进入控制台 API Key 页面；未登录用户由控制台认证保护进入登录或注册流程。次按钮为“浏览模型 / Explore Models”，进入控制台模型广场。

登录与注册由控制台统一处理，目标配置为同时支持邮箱密码和 Google、GitHub 第三方登录。官网不存储认证凭据，也不尝试跨子域读取控制台的本地登录状态。

右侧为代码调用演示卡片，展示平台已确认支持的请求格式。代码卡片支持标签切换和复制操作。正式内容必须与实际端点一致，不展示无法调用的协议或示例模型。

### 4.2 核心能力

使用三张卡片说明：

1. 一个 Key，统一管理。
2. 兼容 OpenAI 与 Claude 的常见接入方式。
3. 根据质量、响应速度、上下文能力和成本选择合适模型。

不显示“50+ 模型”“99.9% 可用性”等未经确认的数据。未来只有在统计口径明确、数据可验证时才增加数值指标。

### 4.3 接入流程

以三个步骤展示：

1. 注册或登录。
2. 创建 API Key。
3. 选择模型并发送请求。

### 4.4 技术兼容性

展示已经确认支持的模型生态、请求格式及客户端。OpenAI、Claude、Cherry Studio、CC Switch 等名称只有在实际接入路径经过验证后才显示。该区域用于说明兼容能力，不暗示官方合作关系。

### 4.5 底部转化区

中文标题：

> 准备好开始构建了吗？

英文标题：

> Ready to start building?

主按钮进入控制台 API Key 页面；控制台负责判断登录状态并引导未登录用户完成登录或注册。

### 4.6 页脚

页脚包含版权、用户协议、隐私政策，以及后台配置中允许公开展示的其他链接。用户协议和隐私政策没有配置时不渲染空入口。

## 5. 视觉系统

- 基础背景使用白色和浅灰蓝，品牌蓝作为主色，青色或紫色只作少量辅助光晕。
- 官网头部高度、Logo 尺寸、导航密度和图标风格与控制台保持一致。
- 页面内容最大宽度约为 1200px。
- 卡片通过留白、细边框和轻阴影建立层级，不使用大面积玻璃效果。
- 中文采用清晰的现代无衬线字体；英文采用 Inter 或同类字体。
- 主按钮沿用控制台的品牌蓝和克制圆角。
- 动画仅包含轻微淡入、上浮和代码标签切换；尊重 `prefers-reduced-motion`。
- 深色主题保持信息结构不变，使用深蓝黑背景、低对比边框和足够的文字对比度。

## 6. 响应式行为

- 桌面：首屏左右双栏，代码演示与主文案并列。
- 平板：保留双栏但缩小标题、间距和代码卡片。
- 手机：首屏改为单栏，代码卡片放在 CTA 下方；主导航折叠为菜单。
- 所有交互控件满足键盘访问、可见焦点和可读的辅助文本要求。

## 7. 多语言与主题

中文和英文分别维护完整内容，不在同一页面同时展示。首次访问可参考浏览器语言；用户主动选择后，以本地偏好为准。

主题默认跟随系统。用户手动选择浅色或深色后保存偏好，避免刷新时闪烁错误主题。

## 8. 数据流

1. 浏览器请求 `siliconfission.com`，Caddy 返回官网静态文件。
2. 官网通过主域名下的同源配置代理读取 New API 公开站点配置和顶部导航。
3. 官网规范化后台导航路径并渲染顶部栏。
4. 用户点击控制台业务入口后跳转到 `console.siliconfission.com`。
5. 控制台负责认证、注册、授权与业务页面跳转。
6. 模型调用继续通过 `api.siliconfission.com` 进入现有网关。

## 9. 故障处理

- 导航配置超时或失败：使用最后一次有效缓存；无缓存时显示基础菜单。
- 后台导航包含无效链接：忽略该项并记录非敏感诊断信息。
- 复制代码失败：选中代码并提示用户手动复制。
- 控制台不可用：官网仍可正常加载，但业务 CTA 显示明确的暂时不可用反馈或由控制台错误页处理。
- 主题或语言偏好损坏：恢复系统主题和浏览器语言默认值。

## 10. 部署与回滚

- 官网构建产物存放在独立目录，并以只读方式挂载给 `sf-caddy`。
- Caddy 为主域名提供官网静态文件，为控制台子域名反向代理 `sf-new-api:3000`，并保持 API 子域名的现有网关转发规则。
- 修改前备份当前 Caddyfile 和现有官网文件。
- 首次上线前确认 `console.siliconfission.com` 的 DNS、HTTPS 证书、OAuth 回调和公开服务器地址配置。
- 上线前确认邮箱密码注册、Google 登录和 GitHub 登录均已在控制台启用；未配置完成的登录方式不在认证页面展示。
- 回滚时恢复原 Caddyfile 和静态资源挂载，不修改数据库或 API 网关。

## 11. 验收测试

- 主域名直接访问、刷新、点击 Logo 均显示同一公开官网。
- 控制台子域名可正常注册、登录、管理 API Key 和访问模型广场。
- 后台修改顶部导航后，官网在缓存周期内同步更新。
- 后台配置不可用时，官网显示缓存或基础导航。
- 中文与英文内容完整切换，刷新后保持选择。
- 浅色、深色和跟随系统主题均正确。
- 主 CTA 在已登录和未登录状态下都能进入正确流程。
- 桌面、平板和手机布局无溢出、遮挡或不可操作元素。
- API 子域名的现有模型请求行为不发生变化。
- 页面不包含未经验证的模型数量、可用率或官方合作暗示。

## 12. 非目标

- 不重做 New API 控制台页面。
- 不修改模型网关、计费、数据库或渠道配置。
- 不在官网重新实现搜索、通知、认证或 API Key 管理。
- 当前不建设文档中心。
